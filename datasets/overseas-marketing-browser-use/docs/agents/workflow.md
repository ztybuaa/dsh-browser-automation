# 文档工作流

本数据集采用“先在独立案例构建工作区打磨、用户确认后同步到宿主仓库 issue”的规格流程。

1. 先读取 `CONTEXT.md` 和相关 ADR，确认使用的领域语言与既有决策。
2. 在 `docs/research/` 记录案例选择和可行性验证，区分候选探索与冻结后的案例。
3. 在 `docs/prds/` 维护 PRD 草案；用户确认后将决策导向的规格同步到宿主仓库的 canonical issue。
4. 用户确认后，才将决策导向的规格发布到外部 issue tracker；issue 不复制无界调研流水。
5. 具体案例和执行 prompt 必须从唯一案例规格派生，避免营销背景、范围和采集计划漂移。
6. 成本优化和内嵌浏览器实现属于独立后续分支，不纳入本 PRD 主线。

本目录只保存文档、研究记录和数据集契约；插件实现、正式测评和评分运行仍由宿主仓库后续 ticket 管理。
